# FrameChoreo 1.0 candidate

This is the **unpublished 1.0.0rc3 candidate**. It broadens the authoring API and
reader experience; it does not increase the capture budgets or promise arbitrary
pandas tracing. The local artifacts are ready for inspection independently of
GitHub/PyPI publication.

## What an author can explain

1. Register separate DataFrames, including monthly files or lookup tables.
2. Combine records, normalize strings, parse numbers/dates, handle missing values,
   choose rows, and remove duplicates.
3. Join tables with explicit keys and cardinality checks.
4. Calculate row-wise values and produce multiple named metrics per group.
5. Reshape between long and wide tables and arrange the final report.
6. Add explanations, chapters, highlighted fields, and playback timing.
7. Export a portable HTML file or display the same player in a notebook.
8. Explain conditional choices, fallback columns, and ordered/grouped window
   calculations while keeping decision inputs separate from value inputs.
9. Compose explicit AND/OR/NOT rules with membership and ranges; audit both
   sides of a join; repeat group metrics beside every original row.

The [API reference](api.md) defines each operation. Results, dtypes, grouping order,
null-key matching, and conversion behavior follow the installed supported pandas
version. The library does not silently convert these into SQL or alternative
mathematical semantics.

## What a reader can do

- Follow the primary analysis through a chaptered step list. Other input tables
  and recorded branches remain reachable through input links and the table catalog.
- Search displayed values across all recorded fields, including hidden fields.
  Search is case-insensitive text matching and does not change the recording.
  Search and visible columns reset on a different table; returning from an origin
  restores the view saved with the selected cell.
- Choose visible columns; at least one stays visible. This is not data redaction.
- Compare the first six recorded rows of an operation's input and result. For
  multiple inputs, choose which one to compare. Comparison is independent of the
  table's search and column visibility. Dtypes and changed-value highlights are shown.
- Inspect missing-cell counts, non-missing unique counts, duplicate rows, and column
  types for the complete recorded table.
- Chart up to 20 rows from the current view using a numeric field. Labels use the
  first text field, or recorded row numbers. Bars are a numeric approximation;
  the recorded text is unchanged. Missing, nonnumeric, non-finite, and integers
  beyond JavaScript's safe numeric range do not receive a misleading bar.
- Select a table cell, comparison value, or bar to inspect its raw inputs and the
  recorded steps traversed by those value references. Return restores the view,
  search, visible columns, row page, and selected value.
- Inspect a distinct decision-input panel for conditional, fallback, and window
  results. An explicit filter shows whether excluded rows failed the condition
  or had a missing comparison, with a link to the original row.
- Expand compound decisions into their atomic true/false/missing checks; the
  final result still follows pandas' three-valued AND/OR/NOT logic.
- Inspect join inputs that had no partner, repeated keys, rows that expanded
  into several matches, and missing-key matches. Open their original rows.
- Switch theme, pause/resume, change playback speed, or reduce motion. System
  reduced-motion preferences take precedence. Tab/arrow navigation works in the
  view selector; normal keyboard controls remain available in tables and forms.

Japanese and English controls are selected with `DataStory(language="ja" | "en")`.
Data names, captions, and notes are authored content and are not machine-translated.

## Honest movement and provenance

Joins move values from labeled right-input cards to their actual result cells.
Sums and other grouped metrics move their own non-missing candidates. Melt, pivot,
arithmetic, fallback columns, and windows can move visible source values to the
corresponding recorded output.
Group colors and numbers survive row-preserving transformations such as sorting.

Only fully visible endpoints are used, with at most 48 moving values. Cards expose
at most 12 distinct join-source cells. The counter describes immediate inputs to
the shown output rows, not the complete recursive source count. Expanded/paged
tables and reader-filtered views remain static. Selecting, scrolling, resizing,
or changing layout settles outdated movement. Direct chapter jumps do not invent
a transition between unrelated layouts; replay visits the preceding scene.

Cell references describe value inputs. The new `case_when`, `coalesce`, `filter_by`,
`window`, and `group_transform` operations additionally record their explicit
decision inputs. These
are different lists. This is not a proof of every control dependency: an arbitrary
filter callback and join matching can affect membership without being another
copy of an output value. Join audits record input coverage separately; they do
not turn a matching key into a copied value. Filled constants, conditional literals, melt column
labels, and absent pivot/concat combinations are distinguished from original
values. The player checks the shape and references of recorded decisions; it
does not independently recompute every pandas comparison or numeric result.

## Compatibility and scope

- Python 3.11+, pandas 2.2.3–3.0.x, and NumPy 1.26+. Runtime dependencies remain
  pandas and NumPy. No frontend package, CDN, server, account, or API key is needed
  to view an exported file.
- Existing 0.1 methods and default budgets remain. New constructor options are
  optional. Older story payloads remain readable by the current player; older
  players cannot be expected to recognize new operations.
- `DataStory`, `StoryFrame`, their documented methods, `col`, `where`,
  `ColumnRef`, `Condition`, `CellOrigin`, `OriginPage`, and exported error
  classes are the intended 1.0 Python surface. Private helpers
  and bundled browser modules are not extension APIs.
- JSON is a versioned display model rather than a pandas round-trip format.
  Pair it with the matching player version. Self-contained HTML does this for you.
- Source columns are unique nonempty strings and cells are supported scalars.
  Nested values, unrestricted many-to-many/cross joins, arbitrary reducers,
  Polars, video export, and disk-backed execution are outside this candidate.
- Capture and playback retain the complete required data in memory. Search,
  paging, hidden columns, and compression never remove it from the exported file.
- Explicit cumulative and group-broadcast explanations stop above 250,000
  value/control references per operation; large captures do not waive this guard.
- The MIT notice covers the bundled player code. User data and narrative keep
  their own license and ownership.

## Try the complete examples

```sh
python examples/retail_workflow.py
python examples/reshape_workflow.py
python examples/decision_window_workflow.py
python examples/compound_conditions_workflow.py
python examples/join_audit_workflow.py
python examples/group_transform_workflow.py
```

The retail example produces a six-metric regional report from two imperfect monthly
inputs; Books revenue is 2700. The reshape example produces North growth of 70,
tracing 150 + 220 − 100 − 200. Both compare full results against a separate pandas
pipeline. Generated files are under `examples/generated/` and contain synthetic data.
The decision/window example follows weekly sales through a target decision,
forecast fallback, lag/diff/rolling/cumulative calculations, and an excluded-row
audit. The output is also synthetic.
The additional examples exercise a three-valued rule, both sides of an outer
join, and group metrics repeated beside the original orders.

See [validation scope](validation.md) for observed environments and limitations.
Release-candidate naming does not establish cross-browser certification, real-user
teaching effectiveness, or readiness for unbounded production datasets.
